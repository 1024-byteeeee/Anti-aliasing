## 安装

1. 安装对应 Minecraft 版本的 Fabric API。Loader 最低版本读取对应 `versions/<版本>/gradle.properties`，未单独指定时为 0.17.2。
2. 将 `build/libs/anti-aliasing-mc<游戏版本>-1.0.0.jar` 放入对应实例的 `mods`，移除旧版，只安装一个对应版本的 JAR。
3. 按 F8 或通过“视频设置”打开设置。安装对应游戏版本的可选 Mod Menu 后，也可从模组列表打开配置菜单。

无需服务器安装。新配置默认开启 SSAA 4×，锐化关闭。配置文件为 `config/anti-aliasing.json`，只读取此文件；已有配置可在设置中点击“恢复默认设置”应用新默认值。
不会检测 Iris 或 Sodium 的安装状态，也不会因它们已安装而停用 TAA。

## 设置

| 控件 | 作用 |
| --- | --- |
| 抗锯齿 | 总开关 |
| 模式 | TAA / SSAA |
| SSAA 倍率 | 4×（宽高2倍）、9×（宽高3倍）、16×（宽高4倍）；只在 SSAA 模式可用 |
| 恢复默认设置 | SSAA 4×、锐化关闭、历史 0.97、Unsharp 备用强度 0.20、CAS 备用强度 1.00、最终画面 |
| 采样周期 | 输入 1～256 的整数，点击应用或完成；默认 8 帧 |
| 历史权重 | 0～1，允许 100%；默认 0.97 |
| 运动时降低历史权重 | 默认开启；关闭后对有效历史保持设定权重 |
| 锐化 | 关闭 / Unsharp / CAS |
| 强度滑块 | 随锐化类型切换，分别保留值；关闭锐化时禁用 |
| 显示 | 最终画面 / 当前抖动帧 / 上一帧历史 / 历史贡献 |
| 清空历史帧 | 重新开始累积 |

即时生效，关闭界面时保存。拖动滑块不反复清空历史，也不逐次写入磁盘。
SSAA 模式禁用历史权重、运动衰减、采样周期、历史调试和清空历史控件；锐化对两种模式均生效，分别保留 TAA 参数和 SSAA 倍率。
界面使用可滚动选项列表。重复点击开关与恢复按钮只更新当前控件；重复按 F8 或打开配置入口不会嵌套设置页。旧配置参数保留，恢复默认设置将启用 SSAA 4×并关闭锐化。
“当前帧”包含投影抖动，仅用于调试；比较原版请关闭 TAA。

## SSAA 渲染

世界、第一人称手部、场景特效和实体描边渲染到独立高分辨率缓冲。绘制 HUD 前，横向与纵向 Lanczos 滤波缩小到原分辨率，再应用可选锐化。HUD、物品栏、菜单和鼠标坐标保持原始分辨率。切换、关闭或缩放窗口时释放并按需重建缓冲。

1080p 输出：4× 对应 3840×2160，9× 对应 5760×3240，16× 对应 7680×4320。倍数表示像素数量倍率，宽高各放大的倍数是 2、3、4。高倍率显著增加 GPU 耗时和显存占用，实际帧率取决于场景和显卡。
内部尺寸超过显卡纹理上限时使用原分辨率渲染，并在设置中显示降低倍率的提示。

## TAA 渲染

- 默认 8 相位亚像素抖动，其他周期使用居中的低差异采样序列，RGB 3×3 邻域裁剪，开启运动衰减时，历史比例为 `历史权重 * (1/3 + 2/3*exp(-像素运动距离))`；关闭时对有效历史直接使用设定权重。
- 世界与第一人称手部均施加相同屏幕像素幅度的抖动。
- 在手部深度清除前保存世界深度。手部使用原版 0.05～100 投影范围，重投影不包含世界相机移动或旋转。
- 历史深度记录前景覆盖，区分世界与手部；仅在慢速轮廓一像素邻域允许保留覆盖历史，避免静止边缘反复拒绝历史。
- 在手持物品、火焰/水下等屏幕效果、物品激活动画、3D 调试十字、实体描边及原版后处理完成后执行 TAA，再绘制 HUD 和菜单。
- 天空忽略相机平移。历史保存未锐化画面，最终输出执行 Unsharp 或 CAS。
- 传送、明显视角跳变、窗口缩放、世界切换、资源重载及长帧中断时重置历史。
- 使用栈内存写入均匀缓冲，复用手部矩阵。
- 使用独立残差纹理保留历史颜色的舍入误差，避免 0.97 等高权重下玻璃细节停止累积；静止时颜色裁剪允许 2/255 的有限余量，移动时收紧。额外占用 8 字节/像素（1080p 约 15.8 MiB），增加一次全屏解析绘制。
- 静止相机直接读取对应历史像素，最终输出和锐化使用精确像素读取。现有 DEPTH32 历史同时保存前景类别与世界深度；当前采样露出背景时，仅在邻域仍支持原细边深度的情况下重建有限覆盖，避免玻璃细边被背景逐渐冲淡。0.4.4 相对 0.4.3 不增加缓冲或绘制次数。

HUD、物品栏与菜单文字保持原版屏幕渲染方式；它们没有透视投影，不进入世界 TAA。
尚未提供实体、手部挥动或屏幕动画的逐物体运动矢量，因此快速动画仍可能产生拖影。透明特效也不总是写入深度。


TAA 显存纹理开销约 28 字节/像素：1080p 55.4 MiB，4K 221.5 MiB。SSAA 自身工作缓冲约为 `8s²+4s+4` 字节/输出像素，`s` 为宽高倍率；1080p 的 4×、9×、16×分别约 87、174、293 MiB。以上不含原版目标、实体描边、透明排序及驱动开销，未测量 GPU 帧耗时。

## 构建与验证

构建配置参考 Carpet AMS Addition：Gradle 9.2.1、稳定版 Loom 1.14.10、Fallen-Breath preprocessor `c5abb4fb12`。使用 **JDK 21** 运行 Gradle 和编译，各版本输出对应 Java 8 / 16 / 17 / 21 字节码。游戏运行时请使用对应 Minecraft 版本所需的 Java。

```powershell
$env:JAVA_HOME = 'C:\Program Files\Zulu\zulu-21' # 改为自己的 JDK 21 路径
.\gradlew.bat clean build -x test
# 只构建一个版本
.\gradlew.bat :1.17.1:remapJar
```

`buildAndGather` 只编译、重映射并汇总七个发布 JAR 到 `build/libs`，不会启动客户端或运行测试。`clean build -x test` 还会生成各子项目源码包，并显式跳过单元测试。单版本产物位于 `versions/<版本>/build/libs`。
首次构建需要联网下载 Gradle、插件、Minecraft 和 Maven 依赖；依赖完整后可使用 `--offline`。正式配置不依赖 `.work` 或机器上的自定义缓存路径。
版本列表位于 `minecraftVersions.json`，主版本位于 `versions/mainProject`，公共源码在 `src/main`，旧版本差异在版本目录中。详见 [多版本构建](docs/MULTIVERSION.md)。
历史游戏验证记录见 [验证记录](docs/VALIDATION.md)。本轮未启动游戏客户端，游戏效果由用户测试；`src/smoke` 和 `src/validation` 不打包进发布模组。

## GitHub Release 自动构建

发布 Release（包括预发布版本）后，`.github/workflows/release.yml` 会检出该 Release 的标签，使用 JDK 21 构建七个版本，并将发布 JAR 上传至该 Release 的 Assets。构建不运行测试，不上传 sources 或 dev JAR；重跑时仅上传尚未存在的同名文件。

发布前将代码推送到 GitHub，更新 `gradle.properties` 中的 `mod_version`，再创建指向包含工作流的提交的标签，例如 `v1.0.0`，并发布对应 Release。草稿状态不会开始构建，无需额外配置个人访问令牌。
